## 2. 字段对应表

### 2.1 金额与业务事实

下列 `amount/unit/currency` 是本轮新增的**适配器输入封装**，不是对旧 Finance Lab 请求新增的强制字段。调用方必须先确认正在转换的字段属于货币金额。

| Finance Lab / 来源 | Risk / 适配结果 | 处理要求 |
| --- | --- | --- |
| 已明确为元的金额字段 | `amount_minor` | 精确乘100后为整数分，不猜单位、不自动舍入 |
| `unit: YUAN` | `unit: MINOR, source_unit: YUAN` | 单位由服务端字段映射指定，不能从数字大小推断 |
| 已经是分的字段，`unit: MINOR` | 同一 `amount_minor` | 只校验，不再次乘100 |
| `currency: CNY` | `currency: CNY` | 本版不做汇率转换，其他币种明确报错 |
| 未知金额 `null` | `null` | 不变成0，不得据此宣称资金足够 |
| Risk 整数分 | `minorToYuan()` 的固定2位十进制字符串 | 用于准确展示与核对 |
| 必须兼容的旧元数值字段 | `minorToYuanNumber()` 的 JSON 数值 | 转回后验证分值往返一致；不能安全保留则报精度错误 |
| 收入、用途、余额的日期与来源 | 原时间、来源、版本信息 | 金额函数不创造到账事实、用途授权或时效证据 |
| 比例、回撤、份额、月数、日期 | 保持原指标单位 | 不属于金额，禁止统一乘100 |

未来接入问答时，余额、当前预留、剩余待付、已有占用、费用和收入到账状态须分别映射。七七当前文字问答并未自动提供这些已核对的结构化事实，本轮不把一句 `question` 当成可信余额或确认记录。

以下是**实际字段与接线提案**。左列已核对 `qiqi/contracts/types.py`、`qiqi/contracts/banking.py`、`qiqi/web/demo_data.py`；右列取自 PR19 的日常网关。该网关尚未合入本轮 main 基线，表格不代表已打通业务入口。

| 现有字段／待补事实 | 日常 Risk 字段 | 接线条件 |
| --- | --- | --- |
| `Portfolio.cash`／组合响应 `cash` | `snapshot.cash_ledger_minor` | 元转分；仅当明确是同一资金池账面余额才映射，投资账户现金不等于家庭全部可用现金 |
| 网关共享账本余额与在途占用 | 内部 `cash_available_minor`、`holds` | 由服务端账本计算；不把 `cash` 直接复制成已扣除占用的可用资金 |
| `TransferRequest.amount` | `action.amount_minor` | 元转分；同时确认动作类型与用途，不能单凭字段名当成投资 |
| Core `proposal.action_parameters.amount` | `action.amount_minor` | 仅在金额语义、币种、元单位已明确且绑定当前完整方案时映射；不修改 Core 原 proposal |
| `Subscription.amount`、`next_charge_at` | 待确认的支出动作金额与日期 | 订阅记录只是待扣证据，用户确认本次安排后才形成 action，不自动新增资金占用 |
| `BillRecord.amount`、`tx_id/ts/note` | 历史流水证据 | 元转分时显式允许负值；负数为已发生支出，不能变成正本金再扣一次；备注不产生授权 |
| 已确认的学费／房租当前预留（现有问答无对应必填字段） | `snapshot.purposes[].reserved_now_minor` | 需独立收集用户确认的当前保护额；不从分类账单或文字自动推定 |
| 同一用途尚未支付金额、付款日 | `remaining_due_minor`、`due_at` | 与当前预留分开记录；历史已支付不再计为待付 |
| 用户确认的现金保底 | `snapshot.hard_floor.state/amount_minor` | 未知不能作为“已确认0元”；与专款重叠时需明确覆盖关系 |
| 工资／其他收入（原 `annual_income_range` 只是区间） | `snapshot.income_events[].amount_minor/status/at/included_in_balance` | 区间不转为确定月薪；明确到账时间和是否已含余额，避免重复加钱 |
| 手续费（旧入口未明确提供） | `action.fees_minor` | 必需但未知时为 null并复核，不默认免手续费 |
| `Position.market_value`、`Portfolio.total_value/total_assets` | 投资诊断证据，金额转分后独立保存 | 不作为可花现金；价格可能超过2位小数，不能套用付款金额精度规则 |
| `quantity`、`return_pct`、`max_total_loss`、`annual_income_range` | 原值及原单位 | 分别是份额、百分数、0—1比例、区间文本，均不直接进入金额函数 |

本轮金额函数只转换单个已明确语义的金额，不自动遍历对象、求绝对值或创造上述缺失字段。字段所有者、资金池范围和用户确认收集将在下一轮业务接线时共同核实。

## 3. 金额适配器

代码：`modules/safety-risk-eval/interface-adapters/money.cjs`。纯函数，使用 BigInt 中间运算，输出可安全表示的整数分，不依赖 npm 包。

```javascript
const { normalizeMoney, minorToYuan, minorToYuanNumber } = require("./money.cjs");
const money = normalizeMoney({ amount: "8000.00", unit: "YUAN", currency: "CNY" });
// { currency: "CNY", unit: "MINOR", amount_minor: 800000, source_unit: "YUAN" }
minorToYuan(money.amount_minor);       // "8000.00"
minorToYuanNumber(money.amount_minor); // 8000, compatible with existing numeric yuan fields
```

输入规则：

- `YUAN` 接受普通十进制字符串、有限数值或明确的 `null`；最多2位小数。`1.005`、`"1.000"` 均拒绝，不默默四舍五入或截去多余0。
- 推荐金额原文使用十进制字符串。若上游已用浮点解析并丢失原始精度，适配器不能还原原文；后续入口应在解析阶段保留十进制信息。
- 不接受空串、空格、逗号、布尔值、`undefined`、NaN、Infinity 或科学记数法字符串。数值形式已经丢失原始文本格式，只按其可验证的数值表示检查。
- 十进制文本最多64字符，超过则在 BigInt 运算前报错；这是防止异常超长输入的技术限制。
- 默认金额非负；负现金流差额仅在调用方明确传入 `allowNegative:true` 时支持，不能借此允许负付款本金。
- `MINOR` 只接受安全整数数值或 `null`。默认范围为 `MAX_MINOR=1_000_000_000_000` 分，沿用日常演示网关技术范围；这不是监管阈值。`maxMinor` 可显式配置，但不超过安全整数范围。
- 适配器不累计工资、合并用途或判断是否重复入账；这些业务核对仍由日常风险引擎完成。调用方需保存原始输入、来源单位及转换后的分值供审计。

## 4. 四态到三态的映射

| 本地 Risk 结果 | 回调草稿 | 适配状态 | 后续处理 |
| --- | --- | --- | --- |
| `ALLOW` | `decision: APPROVE` | `DRAFT_READY` | 仅表示风险意见；正式签名、用户确认及执行检查独立完成 |
| `REVIEW` | `decision: REQUEST_MORE_INFO` | `DRAFT_READY` | 暂停；已发送回调后，补充/接受/修改产生新 Core 任务和 handoff |
| `BLOCK` | `decision: REJECT` | `DRAFT_READY` | 阻止；修改方案需新交接，不覆盖原拒绝 |
| `ERROR` | `callback: null` | `ERROR_HELD` | 走错误通道、保存原因、恢复必需检查；不能冒充业务复核或通过 |

所有输出始终 `dispatch_allowed:false, execution_allowed:false`。模块只生成草稿，不提供网络、签名或发送函数。后续服务端必须读取自有任务、校验最新证据和版本、持久化审计，再按 Owner 规范签名发送。

本模块校验已知字段白名单、关键状态及绑定一致性；这不是完整 JSON Schema 验证器，也不是可信接收服务。正式 HTTP 边界仍需应用官方完整 Schema、请求大小限制、身份/签名和时效校验。

Core 的人工审批行为取决于 `approval.required`：资金调整等需要审批的动作在风险通过后仍等待确认；某些 `NO_ACTION` 等无动作提议可为 `required=false`。本轮既不修改这个字段，也不把任何状态假装成“已完成交易”。本产品涉及资金变动的入口后续仍须有效的完整计划确认。

### 4.1 本轮内部最小 Risk 摘要

`buildRiskCallbackDraft({handoff,risk_result,reviewer})` 中 `risk_result` 只允许以下8个字段：

| 字段 | 类型与来源 |
| --- | --- |
| `risk_check_id` | 服务端保存的程序检查编号 |
| `decision` | `ALLOW/REVIEW/BLOCK/ERROR` |
| `check_complete` | ERROR为false，其余为true；不完整结果不能映射通过 |
| `checked_at` | 含时区的有效 ISO 时间；本模块只校验格式，时效策略留给正式服务 |
| `policy_version` | 实际使用的规则版本；与交接包非空版本一致 |
| `core_binding` | 六项：handoff/task/request/run/audit编号与proposal摘要 |
| `local_task_id` | 本地Risk任务编号，只用于追溯 |
| `reasons` | 每项包含 `rule_id,code,message_zh,status`；ERROR优先于BLOCK，再优先于REVIEW |

该摘要是接线用的内部封装，**不替代完整风险结果、指标、数据版本和证据存储**。原因编号在本模块校验语法；是否来自已发布规则注册表由上游引擎和正式服务保障。模型原文或浏览器传入的同名字段不能被视为服务端有效结果。

### 4.2 正式 callback 的固定10字段

```text
callback_version, handoff_id, task_id, request_id, run_id,
audit_id, proposal_sha256, decision, reviewer, reason
```

`reviewer` 后续必须由可信服务身份提供；样例字符串不是认证。`reason` 长度受官方500字符限制，超限明确报错，完整明细在 `audit_context` 保留。

Core proposal摘要按当前实现对完整 proposal（不含自身摘要字段）原始JSON序列化计算，包含金额、动作和可选 funding。适配器核对摘要但不替换它；不要把请求指纹的排序算法套在 proposal上。后续若需改变序列化约定，应由 Core Owner 升级契约。

## 5. 重试、复核与失败恢复

1. **相同首次回调重发：** Core 返回 `DUPLICATE`，不增加风险决定或执行。
2. **同一 handoff 改结论/原因/身份：** Core 拒绝，不能把复核、拒绝或成功回执覆盖。
3. **已发送 REQUEST_MORE_INFO：** 补充资料或接受软风险后先重新检查，再建立新 Core 任务/handoff，来源保留在 `reviewed_input.source_task_id`。本地 Risk 可保留自己的版本历史，两边编号不混用。
4. **ERROR尚未产生首次业务回调：** 恢复必要检查后，可重新核对原 Core 任务；发送前再次读取最新状态。若任务已取消、终止或已有决定，则走新任务或既有恢复流程。
5. **签名、网络或持久化失败：** 不伪造接收成功；先查询原任务与回执，确认状态后按正式幂等策略恢复。
6. **账户事实与身份：** 交接包 `input_authority=UNVERIFIED_CALLER_INPUT`；即使传输签名有效，也不等于余额已由银行核验。

## 6. 四态完整样例与运行方式

目录：`docs/safety-risk-eval/interface-adapters-v1/examples/`。

- `allow/review/block/error.input.json`：完整 Core 交接包＋最小Risk摘要＋演示reviewer。
- 对应 `.output.json`：适配草稿及本地风险审计关联，ERROR没有合法业务callback。
- `money-vectors.json`：12组正常、未知、精度、单位和币种样例。
- `manifest.json`：明确所有资料虚构、无真实模型调用、未发送回调、未授权执行。

样例借助官方 `buildRiskHandoffPackage()` 生成。模型 `call_succeeded` 等字段为结构测试替身，不能拿来证明真实模型、真实账户或签名联调已经成功。

```powershell
node --test modules/safety-risk-eval/interface-adapters/test/*.test.cjs
node modules/safety-risk-eval/interface-adapters/write-examples.cjs --check
```

测试直接调用当前 Core 的交接构造器、回调校验器和工作流，验证通过后仍等待必要审批、复核/拒绝阻断、重复回执、回调不可覆盖、新任务来源关联。测试不联网、不调用模型、不执行真实交易。
