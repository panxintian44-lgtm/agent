# 最小联合验收清单（v1.1）

> 目的：在同一 staging 版本上，完成 Risk 与 Core/Backend 的可信回写、本人审批、账本原子性的最小闭环验收。
> 当前状态：Risk 侧 v1.1 已完成本地验证与工作台发布；正式联合验收未开始。
> 原则：L3 模拟写入保持关闭，L4 真实交易始终禁止；失败时相关写调用必须为 0；未知回执不得盲目重试。

## 一、验收前置条件（双方共同确认）

| 项 | 要求 | 负责人 | 证据形式 |
|----|------|--------|----------|
| 同一 staging 环境 | 明确主入口、Core / Risk / Finance 源码 SHA、部署 ID、路由及 Owner | 架构 + Core + 部署 Owner | 部署记录 + SHA 对照表 |
| Risk Owner 身份与签名 | 确认正式 reviewer 身份、HMAC 密钥配置方式、签名验证端点 | Core + Vesper | 配置说明（不含密钥值） |
| 接口冻结 | `risk-callback.v1` 十字段不变；评级与验证结果走旁路 | 双方 | 契约文档引用 |
| 测试账号与数据 | 提供可隔离的测试主体、账户、任务 ID 生成规则 | Core / Finance | 测试账号清单 |

## 二、最小验收用例（必须全部通过）

### 1. 正常路径（基线）
- **场景**：用户发起日常资金检查 → Risk 返回 ALLOW/REVIEW → 展示建议与证据 → 用户对完整计划确认 → 回写成功。
- **验收标准**：任务、主体、账户、方案摘要、版本、审批、回执一致；Risk 回写绑定同一 `handoff_id` / `task_id` / `proposal_sha256` / `audit_id`。
- **证据**：正式服务 HTTP 请求/响应 + 审计日志关联记录。

### 2. 硬冲突路径（房租/学费）
- **场景**：拟议投入导致已确认房租或学费被侵占。
- **验收标准**：Risk 返回 HIGH + BLOCK；模型与正式回调不启动；执行端写调用数为 0。
- **证据**：HTTP 记录 + 审计事件。

### 3. 本人审批身份（关键）
- **场景**：仅服务 HMAC 认证，无服务端登录身份的本人批准。
- **验收标准**：不能进入执行；跨用户批准、改参后批准、撤回后重放均被拒绝。
- **证据**：负例 HTTP + 审计拒绝记录。

### 4. 异常与边界

| 用例 | 预期行为 | 写调用数 |
|------|----------|----------|
| 超时 | 返回可识别错误，不自动重试成功 | 0 |
| 过期 | 拒绝，记录原因 | 0 |
| 重复回调 / 幂等 | 第二次不产生新写操作 | 0（或仅首次） |
| 结果未知 | 先核查原执行，不盲目重试 | 0 |
| 存储/审计失败 | 可见错误，不继续执行 | 0 |
| 重启恢复 | 恢复后状态一致，不重复执行 | 0 |
| 批准后改参 | 旧批准失效，重新检查 | 0 |

### 5. 账本原子性（Finance）
- **场景**：reserve → commit / release。
- **验收标准**：同任务幂等；并发占用正确处理；重启后核账一致；失败时资金不被占用。
- **证据**：账本前后余额 + 账户版本 + 审计关联。
