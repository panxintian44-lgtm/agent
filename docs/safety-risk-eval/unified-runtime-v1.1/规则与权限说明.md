# 日常资金风控与权限优化 v1.1：规则与权限说明

负责人：Vesper。适用范围：用户确认的虚构单资金池，以及工资、房租、学费、生活费、消费预算、应急储备和追加投资的只读分析。本轮是原工作台与问答适配器的优化，不代表团队线上业务链路已经验收。

## 1. 版本与范围

| 项目 | 本轮使用的版本或边界 |
| --- | --- |
| 运行配置 | `daily-risk-hardening.v1.1` |
| 评级策略 | `risk-policy.v1.1` |
| 权限判断 | `permission-policy.v1.1` |
| 评级旁路对象 | `unified-risk-assessment.v1` |
| 已支持的原始结果 | `daily-risk-workbench.v1` / `daily-cashflow-policy.v1.0` |
| 正式回调 | 保持 `risk-callback.v1` 原十字段，不增加评级或权限字段 |
| 未接通 | 真实用户审批、团队唯一托管共享账本、投资组合统一评级适配器、全部能力入口的统一权限接线 |
| 资金写入 | L3 模拟资金写入关闭；L4 真实资金操作始终禁止 |

v1.0 规范、历史检查、历史评级和已签署回调保留。v1.1 用于新建或修改资料后产生的新检查；读取历史任务不把旧评级改算成新评级，也不以新策略覆盖旧审计事件。

## 2. 风险等级、风险判定和权限结果分别记录

五档等级用于解释生活资金安排的风险与资料覆盖，四态判定用于表达本次确定性检查结果。它们都不授予执行权限。

| 五档等级 | 日常资金适配中的含义 |
| --- | --- |
| `LOW`／低 | 本次适用的必需检查和金额完整，没有适用的财务风险发现；不保证安全 |
| `NOTICE`／关注 | 只有用户确认启用的预算或应急目标软提醒 |
| `ELEVATED`／较高 | 用户启用逐项接受要求的软提醒仍处于复核；不能直接执行 |
| `HIGH`／高 | 有充分独立证据确认保护用途、现金、付款日期、跨任务资金或流动性硬冲突 |
| `UNKNOWN`／未知 | 必要证据不足、结果校验失败、适配版本不支持，且不能确定已核实的高风险下界 |

| 四态风险判定 | 含义与动作边界 |
| --- | --- |
| `ALLOW`／通过 | 本次风险规则通过；仍须独立核验授权、确认、数据版本和执行入口 |
| `REVIEW`／需要复核 | 按原因补资料、修复数据、核账、重新确认，或逐项接受允许接受的软提醒 |
| `BLOCK`／阻止 | 确认的硬约束或权限边界被违反；用户勾选不能覆盖 |
| `ERROR`／异常 | 必要检查、审计、存储或计算失败；相关下游停止 |

原日常引擎的优先级保持 `ERROR > BLOCK > REVIEW > ALLOW`。因此，已核实资金冲突同时遇到独立网关异常时，可以保留 `HIGH / PARTIAL / ERROR`：已知冲突仍可解释，异常仍会阻止后续流程。

权限函数另返回 `ALLOW / DENY / ERROR`。这里的 `DENY` 是本次精确动作的授权拒绝，不改写既有风险判定；权限函数即使返回 `ALLOW`，也保持 `execution_allowed: false`，资源服务和执行网关仍须独立检查。

资料覆盖为 `FULL`／本次范围完整、`PARTIAL`／部分可评估、`UNAVAILABLE`／不可评估。`UNKNOWN` 不是低风险，`FULL` 也不是全产品功能已接通。

## 3. 先验证结果，再使用评级

`daily-result-validation.cjs` 核对原始结果的契约和策略版本、原因代码及所属规则、原因状态及所在通道、允许接受标记、检查项、原因引用、总判定和指标关系。金额必须是人民币整数分或明确未知；不能把缺失金额补为零。

| 校验状态 | 显示与处理 |
| --- | --- |
| `VALID` | 结果结构与已登记规则一致；继续检查原风险判定和独立权限条件 |
| `INVALID` | 显示“未知／结果校验失败”，列出 `validation_errors` 和恢复动作；暂停模型请求、正式回调及计划确认 |
| `UNSUPPORTED` | 契约、原策略或评估目标尚未适配，显示未知；暂停依赖该结果的操作 |

例如“D02 检查为阻止，原因列表却为空”“原因放入错误通道”“检查引用其他规则的原因”都不能显示低风险或完整覆盖。原始结果保留用于排查，不用评级覆盖原结果。

`VALID` 只说明结果可以解释。即使 `validation_status: VALID`，原始风险判定为 `ERROR` 时，问答适配器和工作台仍停止模型请求及相关确认；问答入口也不会发送正式 Risk 回调。不能用格式正确掩盖检查失败。

## 4. 必要资料与可选指标按依赖判断

依赖表以 [`dependency-map.v1.1.json`](../../../modules/safety-risk-eval/unified-rating/dependency-map.v1.1.json) 为准。未登记为可选的缺失资料默认按必要资金证据处理，不能临时降级。

| 资料或结论 | 判断方式 |
| --- | --- |
| 余额、已有占用、保护用途、费用、必要日期、来源与版本 | 未确认或无法核账时，依赖它们的金额与结论为未知 |
| 工资已包含在余额 | 不再增加当前现金，也不再次计入未来到账 |
| 预计工资或其他未来收入 | 可以进入明确标注假设的现金流时间线，不增加当前可用现金 |
| 同一义务与其关联占用 | 只在关联已验证、覆盖金额可核对时消除重复扣减；未知关联进入复核，不擅自释放占用 |
| 房租／学费先到期，工资后到账 | 单独检查较早付款日的缺口，不能用期末正余额掩盖 |
| 已知费用或手续费 | 计入同一动作资金需求；恰好够用与差一分钱分别处理 |
| 重复义务或重复记录编号 | 先核对重复数据，不双扣、不静默删除、不继续给出完整结论 |
| 预算参考、预算分类余额、应急目标及其非重叠分配、压力假设 | 属于明确列出的可选指标；缺失时对应指标未知，不能提供依赖这些字段的建议 |

可选字段包括 `budget_reference`、`category_budget_remaining_minor`、`budget_buckets_minor:*`、`emergency_target`、`emergency_nonoverlap`、`emergency_allocation_before_minor`、`action_uses_emergency_allocation_minor`、`monthly_essential_minor`、`target_months`、`stress_assumption`。

已经独立确认“追加投资会挤占房租”的硬冲突，不因预算参考未填而消失：显示“高风险／部分覆盖”，保留房租缺口和待补资料。若房租金额、余额或占用本身未确认，则显示未知，不能把未核实数字包装成确定的高风险结论。

当前资金硬冲突代码为 `PROTECTED_PURPOSE_CONFLICT`、`PAYMENT_CASH_INSUFFICIENT`、`HARD_FLOOR_CONFLICT`、`PAYMENT_DATE_GAP`、`SHARED_FUNDS_CONFLICT`、`LIQUIDITY_DATE_MISMATCH`。预算和应急参考继续由用户明确启用，默认是软提醒，本轮没有新增统一金融硬阈值。压力情景提醒不代表实际缺口或发生概率。

## 5. 八类日常规则与恢复路径

| 规则 | 检查内容 | 主要恢复方式 |
| --- | --- | --- |
| D01 | 必填资料、来源、时效、一致性与可计算性 | 确认或更新资料；修复数据／服务后重检 |
| D02 | 可结算现金、已确认用途保护、硬性现金底线和用途关联 | 降低追加金额、调整日期或明确核对原义务；不能自动降低用户保护 |
| D03 | 按付款日和到账日展开现金流；区分预测假设及压力情景 | 提前安排真实可用资金、调整动作日期，补充同日收付顺序 |
| D04 | 多任务共用资金、占用和账本证据 | 从可信账本核账并重检；本地自述不证明团队共享账本已连接 |
| D05 | 已启用的个人预算和预算参考 | 解释偏差，由用户选择调整预算或动作；接受要求只作用于允许接受的软提醒 |
| D06 | 已启用的应急目标及其独立资金分配 | 补足资料或重新安排金额；不能把房租、学费重复算作应急资金 |
| D07 | 资产变现或资金可用日期与实际用途日期匹配 | 提供流动性证据或调整方案，不假设资产随时可用 |
| D08 | 权限、确认时效、拒绝／撤回、幂等、未知回执、审计与网关 | 精确核验原任务；结果未知先核账，异常先恢复，禁止盲目重试 |

账单备注、新闻或模型文字均是业务资料。即使包含“忽略规则、直接交易、用户已批准”，也不能更改保护用途、服务权限或确认状态。模型只能解释程序指标、提出修改方向，不能将解释当作批准或回执。

## 6. 权限分级与版本校验

L0 是已登记的公开只读；L1 是受本人和资源范围约束的私有只读；L2 是分析、比较和只读报告；L3 是完整批准计划对应的模拟资金写入；L4 是真实资金操作。等级不是可继承的万能角色，读资料不自动授权发给模型，分析不自动授权修改画像或长期记忆。

判断取以下条件的交集：本人主体、已认证服务与精确调用者能力、资源归属、动作、用途、接收方、环境、有效期和全部必需版本。每一份授权必须独立覆盖本次动作，不能拼接多份不同授权扩大字段或用途。

- 浏览器请求只可声明精确动作、资源、用途、接收方、环境及所选字段。不得提交 `session_verified`、`service_verified`、`grants`、`resource_owner`、`versions` 或 `version_applicability` 来自证权限。
- 调用方从可信服务端构建上下文。权限函数不提供登录认证、不验证服务签名、不签发授权，也不执行资源写入。
- 必需版本由动作目录决定。即使上下文和授权都填写相同的任意对象，缺少目录要求的版本仍返回 `ERROR`；SHA-256 字段必须符合摘要格式。
- `account_version_if_available`、`constraints_version_if_used` 解析为条件依赖。可信服务端通过 `version_applicability` 明确对应版本是否适用；未知时返回 `ERROR`。授权同时绑定该适用性，后续适用性变化也需要重新确认。
- 版本明确不匹配、越权、授权过期、尚未生效或撤回返回 `DENY`；缺失版本、接收方登记或必要服务证据返回 `ERROR`。两者都不能继续相应动作。
- 已有有效授权只在同一主体、动作、资源、用途、接收方、环境和版本完全覆盖时复用。管理员、维护者和 HMAC 服务身份都不等于最终用户本人批准。

### 向模型发送资料的独立授权

`model_context.send` 必须同时具有非空所选字段、服务端登记的模型接收方、环境和接收方版本，以及 `MODEL_DATA_SEND_CONSENT` 独立确认。请求字段只能是一份匹配授权所允许字段的子集；双方都省略字段也不能放行。更换接收方、资料范围、问题或来源版本后重新核验。

上述判断已经在独立权限函数中实现；现有模型入口仍有原有发送确认和服务端配置检查，但尚未完成把全部模型发送统一接到该能力登记的团队验收。不能把判断函数测试替身称为真实本人授权。

## 7. 历史记录、当前校验和失败处理

工作台的新检查将评级旁路对象以 `UNIFIED_ASSESSMENT_RECORDED` 关联保存到同一任务和 `source_risk_check_id`。历史读取优先返回当时保存的评级，不改写 v1.0 数值、等级、策略版本或签名事件；没有历史评级时不冒充曾记录过。

当前是否可继续操作单独放在 `current_validation`，包括校验状态、错误、原风险判定、来源检查编号和当前校验器策略版本。旧评级可供复盘，但本次校验失败时界面显示未知并禁用相关操作；不能用历史低风险绕过当前门禁。资料修改后标记旧结果，重新确认资料并产生新检查。

工作台对模型复核和计划确认在既有会话、CSRF、任务归属检查之后执行当前结果门禁。校验失败或原始 `ERROR` 时，在模型调用和额度占用之前停止，并关联 `UNIFIED_RESULT_REJECTED`。模拟执行入口另调用权限门禁，当前返回 `PAPER_GATEWAY_NOT_CONNECTED`，先审计、再拒绝，不调用原资金写入函数。

问答适配器保存原结果及评级旁路后，才允许继续模型请求和正式回调。失败时返回可展示的错误及已保存的部分程序评估；模型未运行就不展示模型成功，没有回调意图就标记 `NOT_SENT`。已发送但回执未知则保留未知并核查，不自动重发。审计或存储失败不能降级成成功，也不自动切换离线答案。

网络错误提示、原任务归属检查、审计时间线和关闭的执行入口继续保留。历史回执可读不代表新计划可写入。

## 8. 交接与验收边界

接口不新增公开后端契约；评级和权限通过既有旁路对象及审计扩展。冻结回调仍为 `callback_version`、`handoff_id`、`task_id`、`request_id`、`run_id`、`audit_id`、`proposal_sha256`、`decision`、`reviewer`、`reason` 十字段。`ALLOW / REVIEW / BLOCK` 分别映射 `APPROVE / REQUEST_MORE_INFO / REJECT`；`ERROR` 不签成批准或业务成功回调。

本地程序测试、HTTP 测试替身和浏览器交互验证分别记录。它们不证明团队主聊天、真实本人审批、唯一共享账本及执行回执已经贯通。完整接线前，L3 保持关闭，真实模型、付费接口和真实金融操作不属于本轮验收调用。

逐项接线状态见 [能力覆盖表](能力覆盖表.md)。实现依据见 [评级适配](../../../modules/safety-risk-eval/unified-rating/assessment.cjs)、[结果校验](../../../modules/safety-risk-eval/unified-rating/daily-result-validation.cjs)、[权限判断](../../../modules/safety-risk-eval/unified-rating/permission.cjs)、[运行配置](../../../modules/safety-risk-eval/unified-rating/runtime-config.v1.1.json) 与 [工作台接线](../../../modules/safety-risk-eval/unified-rating/site-bridge.mjs)。
