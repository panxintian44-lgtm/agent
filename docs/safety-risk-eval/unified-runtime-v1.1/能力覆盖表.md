# 日常资金风控与权限优化 v1.1：22 项能力覆盖表

负责人：Vesper。范围：本轮权限判断函数、日常评级与现有工作台接线；不把历史组件、独立函数测试或已登记的能力名视为团队线上联合验收。

## 1. 如何阅读

- **规则已实现**：`permission.cjs` 已实现该动作适用的判断或明确关闭返回；不等于对应业务服务已经开发。
- **入口接线**：区分本轮真正调用新权限函数的入口、仅保留原有局部检查的入口，以及尚不存在的统一入口。
- **仍待联调**：列出解除缺口必须由资源服务提供的证据。责任以模块职责提出，跨模块 Owner 承诺仍待团队确认。
- **关闭**：没有开通路径。L3 等待独立后续任务与联合验收；本版本 L4 始终拒绝。

所有能力的 `execution_allowed` 都不会因本次权限函数 `ALLOW` 而变为 `true`。本轮仅已登记公开帮助读取及现有模拟执行拒绝入口直接调用新权限函数；模型／确认入口增加的是结果校验门禁，不能据此宣称模型发送授权、本人审批和账本已统一接线。

## 3. 本轮额外接线与未闭环点

| 检查位置 | 本轮已实现的控制 | 尚不代表什么 |
| --- | --- | --- |
| 新日常检查／修改检查 | v1.1 结果校验、五档评级、依赖分类和关联审计旁路 | 真实账户余额核验、共享账本或跨场景最终评级 |
| 历史任务读取 | 返回当时保存的评级，另列 `current_validation`；无历史旁路时不补造历史记录 | 用新策略把旧检查改写成更高／更低评级 |
| 模型复核与计划确认 | 当前校验不通过，或原结果为 `ERROR` 时暂停；前端禁用，服务端再检查并审计 | 真实本人登录、正式审批服务、全部模型资料发送统一授权 |
| 问答模型与 Risk 回调 | 原始结果及评级先记录；校验失败／`ERROR` 时不调用模型、不发送正式回调；保留部分结果与错误 | 模型建议可直接执行，或所有团队问答入口均已部署该适配器 |
| 模拟执行 | 当前权限门禁明确拒绝，保留原会话、CSRF、任务归属和审计 | 模拟账本写入成功、完整资金链联合验收通过 |
| 网络／服务异常 | 保留可见错误、停止相关请求、不伪装备用成功；未知回执先核查 | 已实现独立持续监控服务、告警值班或生产级可用性承诺 |

下一阶段由 Core／身份审批、Finance／账本、入口与 Memory 等 Owner 对齐可信上下文和正式服务契约，再逐项接线。Vesper 负责 Risk 检查与验证证据；在同一 staging 部署完成联合验收前，本表不会改成“22 项全部接通”。
