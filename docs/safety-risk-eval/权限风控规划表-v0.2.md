# 第四板块：权限风控规划表 v0.2

更新日期：2026-09-24。状态：**第四板块提案已确定，跨模块待团队确认**。本轮为文档交付，未实现程序，未运行风控功能测试。

依据：团队分工图、最新 SOP、Golden Path v0.1、2026-09-24 需求采访。适用：队内虚构用户、模拟资产、两周以上分阶段开发。本文不是法律合规意见，也不代表其他负责人已承诺接口或实现。

## 一、给队友看的评审概览

### 1. 本版相对 v0.1 的变化

| 主题 | v0.2 决定 |
| --- | --- |
| 画像 | 基础／详细问卷 → 智能体整理 → 用户调整确认；允许后续修改，缺失信息保留未知 |
| 约束 | 演示数值建议须逐项确认才启用；风险指标用于说明，不设首版指标硬拦阈值 |
| 支持资产 | 固定候选池内 A 股普通股票、场内 ETF 与现金；具体板块及 ETF 子类待确认 |
| 数据 | 当前估值／建议用最新可用行情，整段历史模拟用固定回放；故障时按功能分流 |
| 交易模型 | 尽量还原已支持资产的实际规则；缺少必需参数时暂停相关执行，不自动简化 |
| 比较和执行 | 用户约束超限仍可做有风险提示的只读比较；禁止写入模拟账户作为执行方案 |
| 四周计划 | 一次确认整段计划、一次任务完成回放；逐步校验，不真实等待四周、不逐步重复确认 |
| 复核 | 明确补资料、更新数据、改方案、重新确认或查执行状态；首版无人工审核后台 |
| 优先级 | 划分独立开发、完整联调、增强三个阶段，关键测试随阶段交付 |

v0.1 保留在本地历史分支，本次上传仅包含 v0.2。本版保留其 29 个规则编号，修改规则语义时显式说明；新增画像规则 PRF-01—05 和交易规则 TRD-01，共 35 条。v0.1 关于每步确认、风险指标硬阈值及专门人员复核的相关提案由本版替代。

### 2. 用户主流程与第四板块位置

用户选择问卷并录入持仓 → 智能体整理 → 用户确认画像和约束 → 获取行情、分析组合 → 生成和比较方案 → 选择合规的执行方案 → 展示完整模拟计划摘要 → 用户确认 → 一次任务运行整段模拟 → 保存结果、审计与历史版本。

| 阶段 | 第四板块做什么 | 谁提供输入 | 谁实际阻止错误操作（接入责任待团队确认） |
| --- | --- | --- | --- |
| 入口和画像 | 检查身份范围、资料完整度、约束确认及变更影响 | 第二板块可信会话，第五板块问卷与确认 | 第二板块隔离访问；第一板块暂停依赖信息的流程 |
| 数据与方案 | 检查来源、时效、用途、资产范围、资金和已确认约束 | 第一板块汇总方案，第二板块提供画像，第三板块提供数据计算 | 第一板块控制流程；第二板块工具调度与第三板块工具边界拒绝越权 |
| 展示与选择 | 区分只读比较资格和执行资格，解释触发原因 | 第一、三板块提供方案和证据 | 第五板块显示风险与禁用执行；后端仍独立校验 |
| 模拟启动与运行 | 校验整段授权、版本、逐步资金持仓和交易规则 | 第二板块确认记录，第三板块交易状态 | 第一、二板块控制调度；第三板块写入前校验并防重复 |
| 结果与评测 | 生成审计要求，关联事件，验证正常及中止路径 | 各模块产生事件，第三板块返回实际状态 | 第二板块持久化；第一板块协调恢复；第四板块验收 |

第四板块负责规则与判断，不承担问卷页面、行情供应、组合指标计算或交易撮合实现。上述职责仍需第一板块统一共享契约。现有演示中的颜色权限及模拟短信／人脸流程不能直接当作本版的授权机制，具体适配由第一、二、五板块确认。

### 3. 三阶段交付

| 阶段 | 交付内容 | 通过标准 |
| --- | --- | --- |
| S1 独立开发 | 权限、画像确认、约束判定、版本失效、结构化结论；使用虚构输入及依赖替身 | 对应规则正常／异常／边界测试通过；不宣称已完成后端实际拦截 |
| S2 首次完整联调 | 最新行情和回放分流、交易参数、整段授权、逐步执行检查、防重复、基本审计与内容标识 | 正常流程与指定中止路径跑通，执行入口确实拒绝无效请求 |
| S3 后续增强 | 复杂语义检查、扩展攻击集、异常趋势统计 | 单独报告覆盖范围与失败项，不影响 S1/S2 必需安全测试的执行 |

下文 S1、S2 均为首版必做；S3 为后续增强。阶段表示首次验收时间，S1 规则仍要在 S2 验证真实接入点。字段缺失、权限绕过、伪造确认等关键测试不能留到 S3。

## 二、开发前统一的行为与状态

### 4. 双问卷、画像及约束

| 信息 | 采集和使用方式 |
| --- | --- |
| 基础问卷 | 投资目标、投资期限、可接受损失描述、投资经验、需保留现金、禁止投资资产 |
| 详细问卷 | 基础信息加收入、支出、负债、应急资金；金额须标单位，收入支出须标周期 |
| 单独录入 | 当前持仓、可用资金、币种和估值日期，不把问卷中的收入当成可投资现金 |
| 回退基础版 | 详细版可中断；已填写数据保留并可编辑，未填写项标未知；不能把回退视为缺失信息已补齐 |
| 完整度 | 显示本次必需信息是否齐全、缺失项及受影响功能；填写比例不能作为放行依据 |
| 整理与确认 | 分别展示原始回答、模型归纳、系统演示建议；用户可纠正，明确确认后形成生效版本 |
| 建议限制 | 每项数值明确标示为演示建议，用户逐项确认才启用；演示配置及依据待团队确定，不冒充行业标准 |
| 风险偏好 | “最多接受亏损”等描述用于沟通与解释，不能直接换算成单一资产上限或未来损失保证 |

用户可明确回答“不设此限制”，区别于未回答；资金和持仓等执行必需信息仍须提供。详细问卷缺少负债等信息时，不生成依赖这些数据的整体财务承受能力结论。智能体不得补造未知金额或把模型推断作为用户已确认事实。

相关变更：用户修改或外部更新现金／持仓、投资期限、目标、已确认约束，以及实际用于当前建议的财务信息，需要重新检查、重新确认未执行方案。昵称等展示字段变化不影响授权。保留“本次检查用了哪些信息”的依赖清单；无法确定影响范围时要求重新检查。历史结果绑定旧版本，不覆盖成新画像下的结果。执行中的相关变更应停止尚未提交步骤，保留已完成事实，重检后决定剩余计划。

已确认计划自身产生的预期现金／持仓变化，以及已确认历史规则时间表中的版本切换，属于计划内状态推进，只触发逐步校验，不视为外部修改而反复要求确认。偏离计划或事后更换数据、规则包则需要重新检查授权。PRF-04 与 OUT-01 按此区别判断。

### 5. 检查结论与功能资格

| 结论 | 含义 | 后续动作 |
| --- | --- | --- |
| 通过 | 本次用途对应的检查满足 | 可进入下一阶段；通过不等于用户已确认 |
| 需要复核 | 缺少依据或状态待核实，相关功能暂停 | 返回明确恢复类型、负责方与重检条件 |
| 阻止 | 本次动作违反硬性边界 | 修正动作后重检；用户点击确认不能覆盖禁止 |

同一动作的多条结论按阻止 > 需要复核 > 通过聚合，保留全部原因。不同用途分别判断：超出用户仓位上限可显示“比较可用／执行阻止”，不能聚合为整页不可用。通过授权、数据、交易可行性检查是比较的前提；数据不足、真实交易请求或越权不因“仅比较”而豁免。

只读比较为 L2，可生成隔离的假设路径和保存只读报告，不修改用户模拟账户。L3 才能将计划作为执行方案写入模拟账户并保存对应变更。资金、持仓或交易规则不足导致路径不可计算时，应返回原因，不制造一条看似可执行的收益曲线。既有持仓超限仍可只读诊断并标明事实；首版无自动减险豁免，拟执行步骤若仍违反适用硬性约束则停止，例外策略留待团队另议。

| 权限 | 操作 | 条件 |
| --- | --- | --- |
| L0 | 公开读取 | 已注册公开只读工具 |
| L1 | 用户资产读取 | 可信会话、有效访问授权、资源归属匹配 |
| L2 | 分析与只读回放比较 | 访问有权、数据及所需模型有效，无账户写入副作用 |
| L3 | 执行模拟计划、修改模拟账户 | 执行检查通过、用户明确确认完整计划、启动时授权有效 |
| L4 | 真实交易 | 当前版本始终禁止 |

首版使用隔离的虚构用户与账户，无需模拟短信或人脸验证；客户端自报用户编号不能作为可信身份。队内演示身份不得访问真实账户。模拟运行也不产生真实资金交易。

### 6. 数据模式、交易规则与整段授权

- 当前估值和当前建议用最新可用行情；历史回放固定时间窗口、数据版本和规则版本。显示行情时间和用途，不把旧收盘价伪称实时。
- 有效性按资产类型、交易日历、业务用途判断，休市不能简单等同于过期。有效期标准未确认时，不默认放行依赖该标准的功能。
- 实时获取失败或过期时，暂停当前行情功能；用户主动选择历史回放后，检查该模式的数据及计划，再确认执行。不能悄悄使用旧数据生成当前建议。
- 完整回放可独立继续；行情窗口缺失、历史交易规则缺失、费用未知等若影响路径，则暂停相关回放和执行。可继续不依赖缺项的事实分析。
- 首版仅支持固定候选池内 A 股普通股票、场内 ETF 与现金。第三板块需要提供市场／板块／ETF 子类、申报单位、价格精度、交易日历与状态、适用价格限制、可卖数量、费用、资金可用口径及生效区间。支持范围、成交假设和局限必须显示；不能把当前所有股票或 ETF 当成相同规则。
- 回放使用当时适用规则，避免将当前规则倒套整个历史窗口；候选池和指标不得使用回放时点尚不可得的信息。无法满足时限定可支持窗口并说明。
- 整套计划内容包括动作、金额／数量或确定性计算方法、四周安排、价格与费用规则、停止条件。启动前验证用户、计划内容、画像／约束及数据模式版本，确认有效期基于现实时间。
- 启动后在历史时间轴逐步运行；计划不变无需每一步重新确认，也不因历史日期超过现实确认有效期而中止。各步仍须校验资金、持仓、授权撤回状态和适用约束。
- 不得超出确认范围自动重新规划。计划／模式或影响检查的依据改变时，停止未完成部分，重检并重新确认；撤回不能自动反向已完成交易。

### 7. 五种复核恢复动作

| 类型 | 处理方 | 恢复条件 |
| --- | --- | --- |
| 补充资料 | 用户经第五板块；第二板块保存 | 必需信息补齐并按需确认画像 |
| 更新数据 | 第三板块；第一板块重调度 | 对应来源、时点、交易规则及版本齐备 |
| 修正方案 | 用户主动请求，第一板块路由到方案生成模块 | 保持原约束重生成，得到新版本并重检；不自动降低限制 |
| 重新确认 | 第五板块展示，第二板块保存，第四板块校验 | 对完整最终计划得到有效确认 |
| 核查执行状态 | 第三板块查询实际结果，第二板块关联记录 | 状态明确后决定剩余动作，避免重复写入 |

首版不设置人工审核后台。复杂内容暂时无法核实则停止受影响输出，由对应内容生产方修正后重检；不能把“待复核”包装成默认放行。运行服务故障由维护该服务的模块恢复，权限服务不可用时禁止执行。

### 13. 必须联调的串联场景

1. 基础问卷 → 确认画像及演示约束 → 最新行情分析 → 比较方案 → 选择合规计划 → 一次确认 → 完整回放 → 审计可追溯。
2. 详细问卷中断 → 回退基础版 → 缺项保持未知 → 只生成有依据的结论。
3. 实时行情失效 → 当前功能暂停 → 用户明确选择完整历史回放 → 重检及确认 → 运行成功；回放依赖不完整时停下。
4. 超限方案曲线可读且提示清晰 → 执行被后端阻止 → 用户主动重生成 → 原约束保留 → 新版本重新确认。
5. 四周计划在一次任务内逐步运行 → 某步资金或交易条件失败 → 保留已完成步骤 → 不擅自改计划；部分成功如实展示。
6. 确认后更改相关画像／模式／动作 → 旧授权失效；昵称变化不影响；历史结果仍关联旧版本。
7. 用户拒绝、撤回、重复请求、未知执行状态、恶意外部指令与审计故障，各自验证实际拦截与记录。

这些是待运行的用例，本版没有声称它们已通过。关键规则不可只测返回字符串，须验证无不应发生的账户写入或数据泄露。
