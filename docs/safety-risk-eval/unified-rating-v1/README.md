## 3. 最终业务评级：四档＋未知

评级始终绑定`评估对象＋用途＋方案/账户/约束/数据/规则版本`。LOW不表示无损失或永久安全；历史回撤不是未来亏损上限。

| 代码 | 显示 | 定义 | 与处理结果的关系 |
| --- | --- | --- | --- |
| LOW | 低 | 当前用途必需检查完整，无适用风险触发 | 可为ALLOW；仍要权限、本人批准和执行前检查 |
| NOTICE | 关注 | 只有用户确认的软目标偏离，没有复核、硬拦或关键检查错误 | 现行规则允许时为ALLOW＋具体提示；不降低已有REVIEW/BLOCK |
| ELEVATED | 较高 | 回撤、高相关、限定行业未知或合格逐步改善需要复核 | REVIEW；区分可接受风险和必须修复，保留原因 |
| HIGH | 高 | 当前证据独立证实硬性资金/资产/集中度约束违反 | 对执行方案BLOCK；不能靠“愿意承担”覆盖硬限制 |
| UNKNOWN | 未知 | 不能完成当前用途必需评估，且没有已证实HIGH下界 | 缺事实为REVIEW，结构/计算/服务错误为ERROR；不补零、不假造完整评级 |

同时记录`coverage=FULL/PARTIAL/UNAVAILABLE`。R05允许接受的行业未知属于明确的局限例外，可为ELEVATED＋PARTIAL＋REVIEW；余额、身份、版本或计算服务未知不享有这项例外。

C/R机构评级未评定，不阻止有权的确定性预算分析；但不能放行依赖正式适当性匹配的操作。各项完整度只针对本次声明的评估用途，不把无关维度缺失当成已补齐。

### 唯一聚合口径

1. 入口无权或权限验证出错：先拦截，`risk_engine_ran=false`、`risk_decision=null`，业务评级UNKNOWN；不伪造Engine BLOCK。
2. 若已有**不依赖失败字段、绑定当前对象/任务/方案/版本**的证据独立证明硬拦：HIGH/BLOCK。其他检查出错仍放入`check_errors`，完整度PARTIAL，不能显示“全检成功”。
3. 无已证实硬拦，必要检查故障：UNKNOWN/ERROR；必要业务事实待补：UNKNOWN/REVIEW。
4. R05限定局限或其他适用复核：ELEVATED/REVIEW；数据完整时仅软提醒为NOTICE，完全无触发为LOW。
5. 不做加权平均总分。正面信息不能抵消现金缺口、越权或已确认硬约束；所有原因、错误及未知项都保留。

这里的必要检查故障指当前金融评估所需的数据/计算检查。若后续审批、执行或审计控制失败，记录对应控制错误并阻止动作，保留此前已完成且有版本的金融风险记录；不把执行错误改写成新的金融评级，也不把旧评级当成当前执行许可。

**诊断和执行分开。** 原组合可显示HIGH并继续有权的诊断/比较；没有申请执行检查时，`risk_decision=null`并标注未申请执行审核。新执行方案另检，诊断成功不能授予账户写入。

无成交动作的纯现金拟议方案也可主动申请方案Risk检查（UC05），得到该检查的ALLOW；只请求原组合诊断、未申请方案检查的UC26保留null。是否请求Risk检查，与是否实际写资金不是同一开关。

## 4. 保留的固定规则与数值

这些是已确认的产品演示配置，**不是由调研数据拟合出的行业标准**。本轮不训练模型，不新增“风险总分及格线”，也不更改R01—R10编号。

| 检查 | 总资产口径 | 非现金投资口径 | 触发与处理 |
| --- | --- | --- | --- |
| R04 单只资产 | 35% | 50% | 超过才触发；同标的多笔先合并；任一口径超限按硬条件处理 |
| R04 前三资产 | 75% | 90% | 现金不参加排名；不足三项取全部；等于上限不超限 |
| R05 单一行业 | 40% | 60% | 每个已知行业都检查，ETF按已登记行业权重拆分；未知单列 |
| R06 历史最大回撤 | 用户明确确认的复核参考值 | 同一历史口径 | 超过则REVIEW；没有通用默认数值，也不直接把含糊损失描述换算成数值 |
| R07 高相关集中 | 任一对相关系数≥0.8，且合计总资产权重>40% | 不以平均相关性替代 | 两条件同时成立则REVIEW；必须同日期收益序列与有效窗口 |

全现金时投资分母为0，比例标不适用，不能除零或编造行业比例。计算使用未四舍五入值，展示精度不改变判定。原来已经超限的组合不因此失去诊断资格。

### 逐步改善例外仍严格保留

只适用于R04/R05原有超限。焦点必须具体到`指标＋资产/行业＋分母`，所选实例严格下降；两个口径的其他硬超限不新增、不加重。资金、可卖量、备用现金、禁止资产、数据与控制全部满足，才可把剩余超限转成ELEVATED/REVIEW。未知值不能证明改善。

当前Core接受记录、重检与状态迁移协议未完成，所以用户接受复核**不会自动打开L3**；不能把已发REVIEW覆盖成APPROVE。接受行业未知也不能覆盖已知超限。

## 5. 生活资金的统一计算

金额使用CNY整数分；Finance元金额先精确适配，已有分不再乘100。币种/单位不明、非有限数、精度超限或不安全整数，不进入金额计算。不同币种不直接相加。

对**含已占用资金的账面现金**，归一化示意为：

```text
可分配现金 = 账面现金 - 所有有效占用
           - 尚未被同一占用覆盖的未付保护义务
           - 用户确认且不重叠的额外最低现金
```

账本若返回已扣占用的可用额，先按冻结合同映射，不能再次扣占用。每个义务/预留需有标识：同一房租的保护与预留不能扣两次，已支付且已反映到账面的义务不再扣；已包含在余额里的工资不再加。未来工资只在明确标注假设的时间轴预测中出现，到账前不增加当前可预留现金。

按到期日顺序检查，晚到的工资不能掩盖早到的学费缺口。“额外最低现金”必须确认为已有保护用途之外的额外金额；未确认建议不能成为硬限制，也不能默认为0。明确“不设此额外限制”与未回答不同。

虚构例：现金18000元，未付且互不重叠的房租/学费/生活用途共13000元，无其他占用且额外限制明确为0，可分配5000元。投入8000元的缺口是3000元，HIGH/BLOCK；投入2000元只说明该现金条件满足，其余Risk、权限与本人批准还要独立验证。

## 6. 调整后的权限分级

权限是动作类别与资源范围，**不是用户“等级越高、所有资源都可访问”**。机构C5、产品低风险、模型自称已批准、GitHub/Cloudflare管理员身份都不产生资金授权。

| 类别 | 可做什么 | 强制边界 |
| --- | --- | --- |
| L0 | 注册公开来源和演示材料读取 | 工具白名单、用途、频率/费用；不能顺带读取私有数据 |
| L1 | 本人授权范围内的资料、任务、Memory、审计摘要与回执读取 | 服务端可信主体和资源归属；知道编号不是授权 |
| L2 | 分析、草稿、历史只读比较、本人私有报告 | 不修改模拟账户、已确认用途或长期事实；数据发给模型需独立同意 |
| L3 | 完整计划下的受控模拟预留/提交 | Risk条件、本人有效批准、账户版、原子资金和审计齐备；当前统一链路未验收，保持关闭 |
| L4 | 真实资金操作 | 本版本始终禁止，任何用户确认或管理员配置都不能放开 |

另设独立能力：资料发往模型、画像/约束确认写入、Memory确认写入/撤回、导出/删除、审计导出、策略发布和部署管理。每项按主体、资源、动作、用途、受众、环境、有效期和依赖版本授权，不能借L1/L2自动写入。

变更问题/资料范围/接收模型时，相关发送授权失效；金额、账户、计划、用途、相关数据/规则/约束版本变化时，受影响检查和未执行批准失效。昵称、目录排版等无关变化不打断任务。旧结果保留旧版本，不覆盖成新规则下已通过。

撤回/删除覆盖后续摘要、向量索引和缓存；旧报告不能重新成为有效Memory。下载导出文件时仍核对主体、范围、期限和撤回状态。服务HMAC只证明服务，不能证明本人点击批准。

撤回与commit的先后由授权/账本Owner定义的可信原子提交点裁定，不比较浏览器时钟。撤回后禁止新投资，但可信服务仍可按原预留做幂等释放和只读核账；已提交事实不能宣称自动撤销。执行UNKNOWN不自动重发或更换幂等键绕过。

## 7. 四态、审批和接口兼容

业务等级、权限、Risk结论、本人审批、执行状态分别记录。只有所有执行前条件满足，且对应网关真实接通并验收，才可能具备模拟执行资格。本规范/低评级不授予这一资格。

| Risk结果 | 现行Core风险回调 | 含义 |
| --- | --- | --- |
| ALLOW | APPROVE | 风险意见通过，不等于本人批准 |
| REVIEW | REQUEST_MORE_INFO | 补资料/修方案/复核；接受流程未冻结前L3不开放 |
| BLOCK | REJECT | 相关动作禁止，保留全部硬拦原因 |
| ERROR | 不发业务决定 | 修复服务/计算等故障，保持失败关闭，不伪装REVIEW或成功 |

冻结回调十字段不变：`handoff_id, task_id, request_id, run_id, audit_id, reviewer, reason, callback_version, proposal_sha256, decision`。`subject_id/account_id/account_version/constraints_version`、业务评级、完整度和详细原因先放内部评估/审计侧车，正式扩展由架构/Core Owner统一。

内部上下文另记`NOT_REQUESTED/NOT_RUN/INVALIDATED/NOT_REEVALUATED`，解释本次`risk_decision=null`的原因；这些不是第五种Risk结论，也不放进旧回调。后置门禁引用旧结论时必须有原记录、相同任务/提议与版本绑定，不能从存在回执就推导LOW/ALLOW。

审计至少关联：可信主体/账户引用、主任务与追踪编号、提议摘要、数据/规则/账户/约束/授权版本、各维度评级、所有原因/错误/未知、复核接受、本人批准来源及状态、执行/预留/幂等编号、真实结果与恢复事件。禁止记录密钥、完整Cookie/token或无必要的原始财务文本。

## 8. 30组案例怎样使用

`acceptance-cases.json`中的UC01—UC30是**待执行的预期设计**，包括：现金满足/缺口/未知、双口径与阈值相等、行业未知/已知超限、合格和不合格改善、回撤/相关性、硬拦伴随工具错误、跨用户/注入、待批/改参、重放/UNKNOWN、审计失败、Memory写入、原组合诊断、保护额与预留不双扣、软目标和并发。

`FOCUSED_RULE`案例只规定目标规则，其他条件是假定的测试前置；不能当成完整用户输入或真实服务证明。案例的期望ALLOW/LOW不代表现网放行，所有案例保持`NOT_RUN`、`runtime_execution_enabled=false`。

用例文件显式列出合成基线：币种/整数分、余额口径、时间、主体/账户和约束版本、确认来源及测试替身。资金用例按名称引用未付房租/学费/生活义务，个别用例显式删除/覆盖余额；UC28按同一义务ID关联房租预留。基线不是生产默认值，不能为真实请求补造身份、余额或确认。

特别保留：

- UC16：独立证实资金硬拦与另一工具错误并存，HIGH/BLOCK＋PARTIAL＋错误记录。
- UC17/18：入口权限拒绝时Risk未运行，不制造金融BLOCK或声称真实模型被诱导。
- UC20/23：保留原签名风险记录；当前改参或结果未知时，不重写历史批准为新批准。
- UC21/24：LOW/ALLOW明确引用原来已完成且与同一计划/版本绑定的评估；不能从“有回执”或“审计报错”重新推导评级。后置门禁拒绝只说明本次未启动新Risk，不否认历史检查已发生。
- UC26：原持仓HIGH仍可诊断，不能由诊断成功推断执行许可。
- UC28：同一房租保护和已关联预留不双扣，剩余可用额仍5000元。
